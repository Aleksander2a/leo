## Revised decisions

- D-054: exact conversation-native isolation; 1:1 DM uses a current user-and-Leo membership union.
- D-055: invitation/presence enables Leo; strategy/domain association is optional and non-gating.
- D-056: arbitrary conversational intake is primary; typed quote rendering is only an optional
  post-route specialization.
- D-057: durable hierarchical plans, bounded read-only children, replanning/resumption, and
  parent-owned synthesis/verification are required through milestone 5.

These decisions supersede the old mapping-availability, explicit cross-channel grant/cohort,
actor-private-only DM, quote-dispatch, and “subagents later” clauses. Stable milestone IDs remain.

## Implemented revised slices

- Slack accepts arbitrary app mentions across recognized conversation kinds and human 1:1-DM
  messages; the forbidden strategy-mapping availability response was removed.
- Admission snapshots exact sorted context conversation IDs plus a deterministic access hash. A
  non-DM snapshot is exactly the destination; a 1:1-DM snapshot is the paginated current Slack
  membership projection, with DM-only safe fallback.
- Canonical conversations link ingress and harness threads. Valid strategy-default changes do not
  make an invited conversation unavailable.
- Slack history loading is bounded, relevance-ranked, failure-isolated, and unable to broaden the
  admitted projection.
- The live CLI and durable worker use one generic conversational runtime instead of duplicate
  `quote|price SYMBOL` regex gates.
- The coordinator supports bounded parallel batches of independent read tools. Public fetch,
  optional market/SEC adapters, bounded delegation, and dependency-aware child research plans are
  available to the generic model.
- Memory retrieval uses exact `(visibility, namespace)` authorization tuples and source/access
  hashes, preventing visibility-by-namespace cross products.
- The verifier has fail-closed grounding rules for quote, web, SEC, delegated, and planned results;
  context-only conversational answers use an explicit trusted unsourced-completion mode.
- Offline eval scenarios execute the coordinator rather than attesting to invariant strings copied
  from their own fixtures.
